# TENNIS LAB · 첫 번째 웹 프로토타입

HTML·CSS·JavaScript만 사용하는 단일 대학 동아리 데모입니다. PRD·ACCEPTANCE·STORYBOARD는 변경하지 않았습니다. 실제 백엔드 API, 데이터베이스, AI 모델은 없습니다.

## 브라우저에서 실행

Node.js 18 이상이 설치된 환경에서 PowerShell로 실행합니다. 패키지 설치는 필요 없습니다.

```powershell
cd C:\Projects\tennis-lab
node preview.mjs
```

브라우저에서 **http://127.0.0.1:4173** 을 엽니다. 종료는 터미널에서 `Ctrl+C`입니다. `preview.mjs`는 지정된 정적 파일만 읽어 제공하는 로컬 미리보기 도구이며 데이터 처리·저장 API는 없습니다. 포트가 사용 중이면 기존 미리보기 프로세스를 종료한 뒤 재실행하세요.

`index.html`을 더블클릭하면 브라우저의 `file://` 보안 정책으로 JSON 읽기가 실패할 수 있으므로 위 방법을 사용하세요. 첫 실행 시 `sample-data.json`을 읽고, 같은 주소의 브라우저 저장 데이터가 있으면 이를 복원합니다. 다른 포트·호스트 이름·브라우저에서는 저장 데이터가 분리됩니다.

## 첫 버전 구현

- 홈: 현재 선수·경기·저장 리포트 수, 최근 경기, 주요 작업 진입.
- 경기 기록: 회원·선수 등록, 단식 세트 점수 검증, 중복 차단, 경기 저장.
- 자동 집계: 경기 수·승패·승률·세트 득실 및 랭킹. 경기 추가 시 모든 화면을 갱신.
- 랭킹: 공식 데모 순위와 경기 수·승수·승률·세트 득실별 오름·내림차순 정렬, 선수별 기록 연결.
- 개인 대시보드: 선수별 경기 이력, 경기일 순 누적 승률, 저장된 샘플 리포트 재조회. 미경기·분석 이력 없음 상태 포함.
- 영상 분석: 파일을 읽거나 전송하지 않고 고정 샘플 관절 그림·각도·설명 표시. 영상 없이 실행 가능. 실패·인식 불충분 시연 및 결과 저장 지원.
- 반응형: 작은 화면은 한 열 배치, 넓은 표·성장 차트는 내부 가로 스크롤.

## 구현용 임시 규칙 (제안)

PRD의 미정 사항은 여전히 미정입니다. 아래는 프로토타입 실행을 위한 임시 선택이며 확정된 서비스 정책이 아닙니다.

| 항목 | 프로토타입 동작 |
| --- | --- |
| 회원 | 이름·회원 코드 필수. 코드 2~20자 영문·숫자·하이픈, 대소문자 무시 중복 차단. 등록 시 선수로 함께 등록. 동명이인 허용. |
| 경기 | 날짜, 서로 다른 선수 2명, 완료된 2~3세트. 2세트 선승. 각 세트 6-0~6-4, 7-5, 7-6 또는 반대 결과만 허용. 기권·중단·복식 미지원. |
| 중복 | 같은 날짜·같은 선수 쌍·같은 세트 순서별 점수는 차단. A/B를 뒤집고 점수도 뒤집은 경우 역시 차단. 동일 조건의 실제 재대결 구분은 미지원. |
| 통계 | 저장된 완료 경기만 집계. 승률 = 승수 / 경기 수 × 100, 소수 첫째 자리. 미경기 승률은 `—`. 세트 득실 = 획득 세트 − 상실 세트. |
| 랭킹 | 반올림 전 승률 → 승수 → 세트 득실 내림차순. 모두 같으면 공동 순위(1, 1, 3), 이름순 표시. 미경기 선수 제외. 표 정렬과 순위 계산은 별개. |
| 성장 | 경기일 순 누적 승률. 같은 날짜는 등록 순서. 영상 자세 개선·실력 향상을 증명하는 지표가 아님. |
| 영상 선택 | 데모 파일 확장자 MP4/WebM, MIME이 있으면 video/mp4 또는 video/webm, 0바이트 초과·50MiB 이하. 실제 코덱·영상 내용·길이 검증 없음. |
| 분석 | 항상 JSON의 고정 샘플 결과. 실제 관절 인식·각도 측정 없음. 성공/실패/인식 불충분은 사용자가 선택하는 시연 상태. |
| 보관 | 선수·경기·데모 결과는 localStorage. 원본 영상·파일명은 저장·전송하지 않음. 데모 실행 후 파일 선택 참조 해제. 결과는 수동 저장, 같은 결과의 연속 저장 방지. |

저장소 접근이 차단되면 메모리 모드임을 안내합니다. 저장 중 용량 초과 등 오류가 발생하면 변경을 반영하지 않고 오류를 표시합니다. 저장 데이터가 손상되면 원본을 즉시 덮어쓰지 않고 샘플을 표시하며, 다음 저장 또는 초기화 시 교체된다고 안내합니다. 초기화는 화면 하단 ‘프로토타입 규칙·데이터 보관 안내’에서 확인 후 실행합니다.

## 직접 확인할 순서

1. 홈에서 회원·선수 4명, 경기 5건을 확인합니다. 랭킹은 박지우 1위(2승 1패), 김하늘 2위(2승 2패), 이서준 3위(1승 2패), 최유진 미경기입니다.
2. 경기 화면에서 최유진(A) / 박지우(B), 새 경기일, `6-0, 6-0`을 저장합니다. 경기 수가 6건이 되고 최유진은 1승·승률 100%·세트 2/0·랭킹 1위가 됩니다. 개인 대시보드에서도 확인합니다.
3. 같은 경기를 다시 입력하면 중복 오류가 뜨는지 확인합니다. 동일 선수, `6-5, 6-3`, `6-4, 3-6`, 음수·문자, 빈 필수 항목도 확인합니다. 실패 후 통계는 바뀌지 않아야 합니다.
4. 새 이름과 회원 코드 `TL005`로 등록합니다. 모든 선수 선택 목록과 미경기 상태에 반영되고 같은 코드는 다시 등록할 수 없는지 확인합니다.
5. 영상 분석에서 선수를 선택하고 ‘영상 없이 샘플 보기’를 누릅니다. 고정 샘플 표시를 확인하고 결과를 저장합니다. 개인 대시보드의 해당 선수에서 결과를 다시 엽니다.
6. 분석 실패·인식 불충분 시연으로 바꾸면 이전 결과가 숨겨지고 저장되지 않는지 확인합니다. 영상 없이 ‘선택 영상으로 데모 보기’를 누르면 안내가 나와야 합니다. 비영상 파일·0바이트·50MiB 초과 파일도 확인합니다.
7. 새로고침 후 회원·경기·저장 리포트가 유지되는지 확인합니다. 분석 화면의 저장하지 않은 일시적 결과는 복원하지 않습니다.
8. 브라우저 개발자 도구의 모바일 화면(예: 너비 390px)에서 메뉴·입력·표·개인 기록을 확인합니다. 네트워크에는 정적 파일 요청만 있고 영상 전송 요청이 없어야 합니다. localStorage에도 원본 영상·파일명이 없어야 합니다.
9. 하단 초기화를 실행하면 가상 데이터 4명·5경기로 복구되는지 확인합니다.

ACCEPTANCE의 실제 AI 정확도·실제 업로드 실패·서버 원본 미보관 검증은 이 프로토타입으로 완료할 수 없습니다. 실제 서비스의 성공 판정과 데모 확인을 구분하며 ACCEPTANCE 결과는 수정하지 않습니다.

## 코드 검증

```powershell
node --test core.test.cjs
node --check app.js
node --check core.js
```

자동 검증은 샘플 집계·승패·세트 득실·공동 순위·미경기·입력 오류·중복·추가 경기 반영·JSON 복원·손상 데이터 거부를 다룹니다. 브라우저의 화면·localStorage·파일 선택 동작은 위 순서로 별도 확인합니다.

이번 구현에서 도메인 테스트 6개, JavaScript 문법, HTML 식별자·라벨·스크립트 요소 참조, 정적 파일 9개 HTTP 응답 및 POST 거부를 확인했습니다. 실행 환경의 Edge 렌더링·자동 조작이 정상 작동하지 않아 실제 브라우저 상호작용과 모바일 시각 검증은 완료하지 못했습니다. 위 직접 확인 순서로 별도 검증해야 합니다.
